================================================================================
4. AUTENTICACIÓN — BACKEND
================================================================================

Archivos creados:
- middlewares/auth.js — verificarToken, verificarPermiso
- rutas/auth.js — POST /auth/login, GET /auth/me

Dependencias instaladas: jsonwebtoken, bcryptjs

JWT payload incluye: id, nombre, email, empresa_id, roles[], sedes[]
Expiración: 8 horas (1 turno)
Token almacenado en: sessionStorage como 'cero_token'

Endpoints:
- POST /auth/login → valida credenciales, retorna token + datos usuario
- GET /auth/me → retorna payload del token actual

Regla clave en verificarPermiso:
- superadmin_plataforma → bypass directo, sin consultar BD
- Otros roles → consulta permisos_rol en Supabase


================================================================================
5. LOGIN FRONTEND
================================================================================

Archivo creado: public/login.html

Comportamiento:
- Si ya hay token en sessionStorage → redirige directo a /panel
- Submit → POST /auth/login → guarda token → redirige a /panel
- Error → muestra "Credenciales inválidas"
- Diseño oscuro consistente con el panel

Rutas en index.js:
- GET / → redirect a /login
- GET /login → sirve login.html
- GET /panel → sirve index.html (protección real en JS cliente)


================================================================================
6. CONTROL DE ACCESO POR ROLES
================================================================================

Frontend (sidebar + router):
- getRolesFromToken() decodifica JWT en base64 sin verificar firma
- Sidebar oculta items según rol del usuario
- Router bloquea navegación a rutas no permitidas → muestra "Sin acceso"

Matriz de visibilidad:

Módulo            | superadmin_plat | superadmin_emp | administrador | supervisor

Posoperacionales  | ✓              | ✓              | ✓             | ✓
Tanqueos          | ✓              | ✓              | ✓             | ✓

Conductores       | ✓              | ✓              | ✓             |
Alertas           | ✓              | ✓              | ✓             | ✓
Sedes             | ✓              | ✓              |               |
Usuarios          | ✓              | ✓              |               |

Backend: verificarPermiso() aplicado a todos los endpoints del panel.
Permisos base sembrados en tabla permisos_rol al iniciar el servidor.

Archivo creado: data/permisos.js — classifyRoleName(), getAllowedCanonicalRolesForItem()

7. MÓDULOS NUEVOS DEL PANEL
================================================================================

7.1 Módulo Conductores (completado antes de v15, documentado aquí)
- Stat cards: Total, Activos, Inactivos, Licencia vencida
- Tabla: Nombre, Cédula, Cargo, Categoría, Licencia vence, Estado
- Drawer: detalle completo + Editar + Activar/Desactivar
- Fix FK Supabase: usuarios_roles!usuarios_roles_usuario_id_fkey

7.2 Módulo Sedes
- Stat cards: Total, Activas, Inactivas
- Tabla: Nombre, Ciudad, Dirección, Empresa, Estado
- Drawer: detalle + Editar + Activar/Desactivar
- Join con empresas para mostrar nombre en vez de UUID
- Fix: campo activa (no activo) en Supabase

Endpoints: GET/POST /api/sedes, PUT /api/sedes/:id, PATCH /api/sedes/:id/estado

7.3 Módulo Usuarios y Roles
- Stat cards: Total, Activos, Inactivos
- Tabla: Nombre, Email, Empresa, Roles, Último acceso, Estado
- Drawer: detalle + Editar + Activar/Desactivar + Cambiar password + gestión roles
- Modal crear: nombre, email, password, empresa_id
- Sección roles en drawer: lista roles con ×, select + sede + Asignar
- Password nunca expuesto en respuestas (select explícito)

Endpoints: GET/POST /api/usuarios, PUT /api/usuarios/:id,
PATCH /api/usuarios/:id/estado, PATCH /api/usuarios/:id/password,
GET/POST /api/roles, GET /api/usuarios/:id/roles,
POST /api/usuarios/:id/roles, DELETE /api/usuarios_roles/:id

7.4 Módulo Posoperacionales
- Stat cards: Inspecciones hoy, Con novedades, Mostrando
- Tabla: Fecha/Hora, Placa, Vehículo, Conductor, KM inicial, KM final, Estado
- Drawer: detalle completo + Ver PDF
- Filtros: rango fechas (default hoy), placa, estado
- Nota: usa conductor_nombre del registro (no join) — posoperacionales no tiene conductor_id

Endpoint: GET /api/posoperacionales con filtros fecha_inicio, fecha_fin, placa

7.5 Módulo Tanqueos
- Stat cards: Tanqueos hoy, Total litros hoy, Mostrando
- Tabla: Fecha/Hora, Placa, Vehículo, Conductor, Litros, KM, Valor
- Drawer: detalle completo + foto si existe
- Filtros: rango fechas (default hoy), placa

Endpoint: GET /api/tanqueos con filtros fecha_inicio, fecha_fin, placa
