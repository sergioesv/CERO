3. DASHBOARD — BACKEND (3 ENDPOINTS)
================================================================================

Archivos creados:
- data/dashboard.js — lógica de agregación completa
- rutas/dashboard.js — rutas Express

3.1 GET /api/dashboard/general
Parámetro: ?periodo=hoy|semana|mes (default: semana)
Retorna:
- Índice de Seguridad Operativa (score 0-100 con desglose)
- KPIs de seguridad (riesgos, cumplimiento, activos, documentación)
- KPIs financieros (ahorro, costo diario, sanciones prevenidas)
- Situaciones que requieren atención (anomalías detectadas)
- Decisiones del supervisor (autorizadas, taller, pendientes)
- Actividad reciente (últimos 20 eventos sin placas)

3.2 GET /api/dashboard/activos
Parámetros: ?periodo=hoy|semana|mes&tipo=todos|vehiculo|escalera|...
Retorna:
- KPIs operativos (inspecciones, novedades, bloqueos, días fuera servicio)
- Novedades por mes (6 meses, barras apiladas)
- Ítems con más novedades (top 10)
- Activos que requieren atención (con placas)
- Reincidencia (misma novedad 2+ veces en 90 días)

3.3 GET /api/dashboard/indice
Retorna desglose del cálculo del Índice de Seguridad Operativa:
- 5 componentes con valor, peso y aporte
- Pesos leídos de configuracion_sede
- Período: últimos 30 días

Fórmula del índice:
score = Σ (valor_componente × peso / 100)
- cumplimiento_inspecciones (peso 30): preop realizados / esperados
- bloqueos_resueltos (peso 25): con decisión / total
- documentos_al_dia (peso 20): SOAT + tecno vigentes / total
- novedades_criticas (peso 15): 100 - (pendientes × 10)
- tiempo_respuesta (peso 10): basado en minutos promedio de respuesta

Bugs corregidos durante implementación:
- parsearNovedades(): fix para JSONB que llegaba como string
- riesgosPrev: pasaba objeto entero en vez de .novedades
- empresa_id: obtenido via JOIN sedes (no existe en vehiculos)
- preoperacionales.placa → vehiculo_placa (campo correcto)
- conductor_nombre eliminado del INSERT posoperacional

5. FIX POSOPERACIONAL WHATSAPP
================================================================================

El posoperacional estaba roto desde v15. Diagnóstico y corrección:

5.1 Bug 1 (ALTA): construirAlertasPosoperacional no existía
- cierre.js llamaba alertasReglas.construirAlertasPosoperacional()
- La función no existía en modulos/alertas/reglas.js
- Fix: eliminar llamada y requires de alertas — el posoperacional
  no necesita sistema de alertas como el preoperacional

5.2 Bug 2 (MEDIA): estados sin prefijo POSOP_
- estado.js asignaba 'ESPERANDO_FOTO_ODOMETRO' sin prefijo
- flujo.js esperaba 'POSOP_ESPERANDO_FOTO_ODOMETRO'
- Fix: ESTADOS exportado desde estado.js, usado en flujo.js

5.3 Bug 3 (ALTA): campo conductor_nombre no existe
- INSERT intentaba guardar conductor_nombre en posoperacionales
- La tabla solo tiene conductor_id
- Fix: eliminar campo del INSERT, usar solo conductor_id

5.4 Bug 4: preoperacionales.placa no existe
- Queries nuevas usaban .eq('placa', ...) en vez de .eq('vehiculo_placa', ...)
- Fix: corregido en data/posoperacionales.js

5.5 Bug 5: responderMenuDesdeModulo no definido
- Referenciado en flujo.js sin estar importado ni definido
- Fix: reemplazado con nav.textoMenuPrincipal()

Resultado: posoperacional probado end-to-end, PDF generado y enviado ✓

6. UNIFICACIÓN DE FLUJOS — ENTRADA NUMÉRICA
================================================================================

Decisión de campo: un operario con una mano ocupada (linterna, herramienta)
necesita tocar un solo número, no escribir texto. Regla universal aprobada:
TODO se responde con números.

6.1 Módulos compartidos creados

modulos/vehiculos/compartido/kilometraje.js
- evaluarKilometrajeContraHistorico()
- procesarFotoOdometro()
- registrarKilometrajeConfirmado()
- manejarConfirmacionOdometro()
- manejarOdometroManual()

modulos/vehiculos/compartido/navegacion.js
- esAtras(), esMenu(), esOpcion()
- PIE_NAV, PIE_MENU
- textoMenuPrincipal() — texto del menú unificado

6.2 Cambios en preoperacional

Firma:
ANTES: "Escribe SI para firmar"
AHORA: "1️⃣ Firmar y cerrar / 2️⃣ Corregir"

Observación:
ANTES: texto libre o "no"
AHORA: "1️⃣ Sin observaciones / 2️⃣ Escribir observación"
Estado nuevo: OBSERVACION_TEXTO para texto libre

Fotos adicionales:
ANTES: "envía fotos o escribe no"
AHORA: "1️⃣ Continuar sin fotos" (pendiente ajuste de formato)

6.3 Posoperacional reconstruido

Flujo limpio con 9 estados POSOP_:
POSOP_ESPERANDO_PLACA → POSOP_ESPERANDO_FOTO_ODOMETRO →
POSOP_ODOMETRO_CONFIRMACION → POSOP_ODOMETRO_MANUAL →
POSOP_NOVEDADES → POSOP_DESCRIBIR_NOVEDADES →
POSOP_OBSERVACION → POSOP_OBSERVACION_TEXTO → POSOP_CONFIRMACION

Todo con números:
- Novedades: 1️⃣ Sí / 2️⃣ No
- Observación: 1️⃣ Sin obs / 2️⃣ Escribir
- Firma: 1️⃣ Firmar / 2️⃣ Corregir

6.4 Otros módulos corregidos
- tanqueo/flujo.js: eliminado responderMenuDesdeModulo, usa nav
- inscripcion/flujo.js: eliminado responderMenuDesdeModulo, usa nav
- canales/whatsapp.js: usa nav.textoMenuPrincipal()

6.5 Verificación
- grep "Escribe.*SI.*firmar": 0 resultados ✓
- grep "responderMenuDesdeModulo": 0 resultados ✓
- Preoperacional probado end-to-end ✓
- Posoperacional probado end-to-end ✓
